Consistent capitalization helps users understand what is a named product or feature versus a general concept or action. In payment and technical experiences, incorrect capitalization can create confusion, imply functionality that doesn't exist, or suggest a level of formality that isn't intended.

This section defines how to determine whether a term is a proper noun or a common noun, and how to apply that decision consistently across UI, documentation, and supporting content.

## Governing Rule

Capitalize a term only when it refers to an official, named product, feature, service, or program. If a term describes a behavior, configuration, concept, outcome, or general capability, it should be treated as a common noun and follow standard sentence casing. When in doubt, default to common noun and escalate for confirmation.

## Proper Nouns (Capitalize)

A proper noun refers to a specific, officially named entity that users can identify, select, enable, or manage. **Proper nouns include:** product names, platform tools and services, official program names, branded features, acronyms or abbreviations that represent named systems.

**Proper nouns should:** always use the approved spelling and capitalization, never be altered for sentence flow, be consistent across UI, documentation, and support content.

For a comprehensive and authoritative list, refer to the KUBRA Product Name Usage and Trademark Guidelines.

## Common Nouns (Do Not Capitalize)

The following terms are not proper nouns and should follow standard sentence casing, even if they are domain-specific or appear technical. **Common nouns include:** general financial concepts, system behaviors or processes, internal classifications or abstractions, features when referenced generically.

## Descriptor vs. Proper Noun Usage

Some terms may appear capitalized in one context and lowercase in another. This distinction depends on how the term is being used, not the words themselves.

**Use sentence case when the term acts as a descriptor.** If the term describes a general action, capability, or outcome, treat it as a common noun.

> Enable this setting to receive payment reminders for your contacts.

Here, "payment reminders" describes a behavior, not the named SMS program.

**Use title case when referring to the named feature or program.**

> Manage Payment Reminders in your notification settings.

## Acronyms and Capitalization

- Acronyms representing named systems or programs are treated as proper nouns and remain fully capitalized.
- Acronyms that describe general processes or technical concepts follow standard sentence casing rules when spelled out.

**Documentation rule:**

1. Spell out the full term on first mention
1. Include the acronym in parentheses
1. Use the acronym consistently thereafter

> The System Usability Scale (SUS) is used to evaluate usability. SUS results are reviewed quarterly.

## UI-Specific Guidance

**In UI copy:** use capitalization to signal selectable or configurable entities; avoid capitalizing concepts that users cannot directly act on; do not introduce new capitalization for emphasis.

**In tables, labels, and menus:** preserve official capitalization for proper nouns; do not "normalize" product names to match sentence case; avoid mixing proper and common noun usage in the same UI surface.

## Approved Proper Noun Usage

| Term | Notes |
|---|---|
| Pay-by-Text | SMS program name (not "Pay by Text") |
| EZ-PAY | Product name (not "EZ-Pay," "EZ PAY," or "Ez Pay") |
| CNAME | Abbreviation/acronym (not "Cname" or "cname") |
| Storm Center | Product name (not "StormCenter") |
| IncidentWatch | Product name (not "Incident Watch") |
| Image Library | Platform tool/service name |
| Payable Types | Platform tool/service name |
| Retail Cash Payments (RCP) | Platform tool/service name |
| Activity Alerts (can be shown as common) | SMS program name |
| Payment Reminders (can be shown as common) | SMS program name |

## Approved Common Noun Usage

| Term / Phrase | Notes |
|---|---|
| PAN validation | Technical process |
| service fee | Financial concept |
| transaction division (TD) | Descriptor; capitalize only when starting a sentence |
| workspace | Generic UI concept |
| snapshot | General system artifact |

## What to Avoid

- Capitalizing for emphasis
- Creating new "informal" variants of product names
- Inconsistent casing across similar UI surfaces
- Treating internal terminology as proper nouns without approval

## When in Doubt

1. Ask: Is this an official, named product, feature, or program?
1. Ask: Can the user directly select, manage, or configure it?
1. Check the Product Name Usage and Trademark Guidelines
1. Default to sentence case and escalate for confirmation
