---
title: "Tables"
blurb: "When to use a table, naming, and formatting rules."
---

Tables organize structured data and allow users to quickly compare information.

## When to Use Tables

Use tables when:

- Presenting structured or repeatable information
- Comparing multiple items or attributes
- Displaying lists with multiple properties

Avoid tables for simple lists or short content.

## Introducing Tables

- Refer to tables as "this table" or "the table"
- Do not use "the following table"

::: do

- *This table outlines supported payment methods*

:::

::: dont

- *The following table outlines supported payment methods*

:::

## Naming Tables

- Give tables a clear, descriptive name
- Ensure users understand what information the table contains

::: do

- *Supported payment methods*
- *Error types and resolution steps*

:::

::: dont

- *Table #1*

:::

## Column Headings

- Use title case for column headings
- Keep headings concise and descriptive

::: do

- *Payment Type | Processing Time | Status*

:::

::: dont

- *payment type | processing time | status*

:::

## Table Content

- Capitalize the first word of each entry
- Capitalize proper nouns as required
- Maintain consistent formatting across rows

::: do

- *Pending*
- *Completed*
- *EZ-PAY+*

:::

::: dont

- *pending*
- *completed*
- *ez-Pay+*

:::

## Do Not

- Alter capitalization of product names or technical terms
- Overload tables with excessive content
- Use tables when a list would be clearer
