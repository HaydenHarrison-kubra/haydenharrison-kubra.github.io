---
title: "Abbreviations and Acronyms"
blurb: "When abbreviations are acceptable in UI vs. docs."
---

## In User Interface (UI) Copy

### Avoid abbreviations and acronyms by default

::: do

- *Routing number*
- *Card number*

:::

::: dont

- *RTN*
- *PAN*

:::

### Use only when widely recognized

::: do

- *SMS*
- *PIN (if appropriate for your users)*

:::

### Do not introduce new acronyms in UI

::: dont

- *"Enter your TD"*
- *"Configure CNAME settings"*

:::

## In Documentation and Help Content

### Spell out on first use

::: do

- *System Usability Scale (SUS)*
- *SUS results are reviewed quarterly (subsequent use)*

:::

## In Technical or Admin Interfaces

Acronyms may be used more frequently, but must still be accurate, consistent, and defined if not universally understood.

## Time

Use ET unless specifying daylight or standard time is necessary.

::: do

- *a.m. / p.m.*
- *ET (preferred for general use)*

:::

::: dont

- *Mixing EST/EDT unless accuracy is required*

:::

## Days and Months

::: do

- *Mon, Tue, Jan, Feb (UI constraints)*
- *Monday, January (long-form content)*

:::

## Currency

::: do

- *$125.00*
- *CAD $125.00 (if needed for clarity)*

:::

## Avoid in Consumer UI

::: dont

- *PAN*
- *TD*
- *Internal system abbreviations*

:::
